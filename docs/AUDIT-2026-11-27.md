## 1. Résumé exécutif

Le dépôt initial était un petit prototype V1. Il ne contenait pas une plateforme OSINT complète ni de base OSINT existante. Le travail de la branche `develop/mega-expansion` a ajouté une architecture Express/PostgreSQL et plusieurs modules fonctionnels dans le code source.

L'état actuel est **un socle avancé en développement, pas encore une plateforme de production complète**. Le frontend statique et le service API Render ont tous deux eu des déploiements confirmés `live`. La base PostgreSQL OSINT dédiée n'est pas encore présente. Les routes publiques de l'API peuvent démarrer, mais les comptes, sessions, dossiers, rapports persistants, notifications et automatisations dépendant de PostgreSQL répondent indisponible jusqu'à la création de la base dédiée.

Aucun service ou aucune base Dust Siege/Warworld ne doit être réutilisé. L'unique base PostgreSQL recensée dans le workspace est `warworld-game-db`, qui appartient à l'autre projet et reste strictement hors périmètre.

## 7. Authentification et sécurité

Contrôles existants dans le code :
- Hachage de mot de passe PBKDF2-SHA256 avec 310 000 itérations et sel aléatoire.
- Sessions opaques aléatoires, hashées en base, avec expiration et révocation.
- Cookie HttpOnly pour les clients same-origin.
- Mode Bearer ajouté pour le frontend statique cross-origin ; le jeton est conservé dans `sessionStorage` pendant la session du navigateur et transmis sur HTTPS. Cela évite de dépendre de cookies tiers sur `onrender.com`, mais rend le jeton accessible aux scripts de la même origine : CSP stricte, échappement HTML et prévention XSS doivent donc rester prioritaires.
- Jeton CSRF, vérification d'origine, CORS à origine autorisée et en-tête Authorization autorisé.
- Helmet, limite JSON, rate limiting, Zod et validation des IP publiques.
- Requêtes SQL paramétrées dans les routes examinées.
- Clés API côté serveur uniquement ; pas de clés fournisseur dans le dépôt ou le frontend.

À renforcer avant production :
- Vérification complète du traitement d'erreurs Express et journalisation structurée.
- Tests automatisés CORS/preflight et parcours navigateur multi-origines.
- Revue SSRF complète pour chaque nouvel appel réseau.
- MFA, récupération de compte et vérification d'e-mail si nécessaires.
- Limites/quota par compte et politique de conservation/suppression RGPD.
- Gestion sécurisée des pièces jointes et stockage objet privé si elles sont ajoutées.
- Sauvegarde/restauration PostgreSQL testée.
- Revue XSS des templates HTML et des exports ; la CSP actuelle n'est pas une preuve d'absence de XSS.
